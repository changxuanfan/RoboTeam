What is new

Many arms, long runs, and a world that never waits.

Earlier benchmarks give an agent one to four arms, mostly for minutes, often pause the world while it thinks, or tell it where every object is. RoboTeam takes all three away.

  • Up to 16 arms, up to 24 hours

    Teams of 4 to 16 arms share one task, and one run can take a full day of work.

  • The clock never stops

    The hall runs in real time and does not wait while an agent thinks. A run ends when the agents say they have finished, or after 24 hours of work.

  • Cameras only, no shortcuts

    No object positions and no depth: the agents measure the world from pictures. When they say they have finished, an evaluator they cannot reach checks the world itself.

How a run works

Inside one real run.

Agents work in a loop: look through the cameras, decide, send one command to one arm, and look again. Here is that loop in a run of gpt-6.1-sol on a Transport task with 8 arms, which it finished with all 24 items in place.

  1. 1

    See

    Only pictures

    Each arm has cameras. No positions come with the pictures: the agent has to work them out.

  2. 2

    Decide

    Split the work

    Early in the run, the controller starts a helper and hands it two arms.

    “Deliver one yellow source C cube into B_slot2, seated released stable, using B/C …”

    Controller to a new helper
    • 2arms handed over, B and C
    • 24robot actions by the helper
    • 7.8minutes until the arms come back
  3. 3

    Act

    One command, one arm

    Each move is one call to the robot tool. The call can ask for a fresh picture when the move ends.

    The agent sendsmove arm A to (−0.107, −0.973, 0.95) m at 0.12 m/s, then show camera A_front
    The robot tool answers

    Completed, with a fresh picture from A_front

  4. 4

    Check

    Notice, and retry

    Later another helper grasps with arm C. The gripper closes at 0.065 m, not the 0.06 m expected. Nothing says what went wrong: the agent looks at the pictures and tries again.

    The agent sendsgrasp with arm C, expecting 0.06 m, then show C_front and C_side
    The robot tool answers

    Grasp stopped outside expected object-width tolerance
