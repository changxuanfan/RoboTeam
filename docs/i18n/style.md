# 中文版排版规则

适用于中文版的 README、文档、项目网页，以及宣传片和图表里的中文。术语的写法见 [术语表](glossary.md)。

## 一、文字

### 中英文混排

- 中文和英文、中文和数字之间，加一个半角空格。
  - 对：`gpt-6.1-sol 完成了 36 个任务中的 28 个。`
  - 错：`gpt-6.1-sol完成了36个任务中的28个。`
- 全角标点和英文、数字之间不加空格。
  - 对：`这次运行用了 Codex，耗时 3.5 小时。`
- 链接、代码格式（反引号）的两侧，按同样的规则加空格。
- 英文术语保持原来的大小写和连字符：`Single-agent`、`input tokens`、`gpt-6.1-sol`。

### 标点

- 中文句子用全角标点：，。、；：？！“”（）——。
- 句子里只有英文时（例如图表标签、按钮旁的短语），用半角标点。
- 并列的英文名称之间用顿号：`Transport、Mosaic、Relay、Dial`。
- 引用英文原文（例如给 agent 的提示词、报错信息）时，原文照抄，外面用中文引号“”，或者放进代码格式。
- 不用感叹号，不用省略号表示语气。

### 数字和单位

- 数字一律用阿拉伯数字，半角：`36 个任务`、`16 条机械臂`。
- 数字和单位之间加空格：`24 h`、`14.5 mm`、`3.5 小时`。
- 倍数写作 `3×`，正文里写"3 倍"。
- 百分号紧跟数字：`34%`。
- 大数字不用千位分隔逗号：`3830 次`，但英文标签里照原样（`1,500×`）。
- 小数点、版本号、尺寸保持原样：`128 × 80`、`1280 × 800`、`v4.1`。
- 不要因为翻译改动任何数字。中英文版的数字必须一致。

### 句子

- 用短句，一句话说一件事。
- 不用"进行""实现""赋能""一系列"这类空泛的词，直接写做了什么。
- 不用"我们很高兴""值得注意的是"这类开场。
- 被动句改成主动句："任务由团队完成"改成"团队完成了任务"。
- 第一次出现的术语，在后面用一个短句解释，不加括号注释的长句。

## 二、文档的结构

- 文件放在 `docs/zh-CN/` 下，路径和文件名和英文版完全相同。
- 每篇开头两行：
  - 第一行：链到英文版的 "English"，后面接 "| 简体中文"。例如 `docs/zh-CN/benchmark/rules.md` 的 English 链到 `../../benchmark/rules.md`。
  - 第二行：`> 本文译自英文版（commit abc1234），内容以英文版为准。`
- 标题翻译成中文，但在标题前保留英文版的锚点，让同一个链接在两种语言里都能用：
  ```markdown
  <a id="a-run-in-six-steps"></a>
  ## 一次运行的六个步骤
  ```
- 代码块、命令、输出、配置、文件路径一律不翻译，代码块里的注释也不翻译。
- 链接：目标有中文版的，链到中文版；没有的，链回英文版。
- 给 agent 看的内容（`prompts/`、任务说明、robot tool 的返回信息）不翻译，引用时照抄英文。
- 图片的替代文字（alt）翻译成中文。
- 不提在投的会议。

## 三、项目网页

### 字体

不下载中文字体。英文字母仍用现在的字体，汉字交给系统字体：

```css
:root:lang(zh-CN) {
  --sans: "IBM Plex Sans", "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", "Noto Sans SC", sans-serif;
  --display: "Space Grotesk", "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", "Noto Sans SC", sans-serif;
  --mono: "JetBrains Mono", "PingFang SC", "Microsoft YaHei", monospace;
}
```

### 字号、行高和字距

| 用途 | 英文版 | 中文版 |
| --- | --- | --- |
| 正文 | 15–17 px，行高 1.55 | 16 px，行高 1.75 |
| 每行长度 | 约 66 个字符 | 约 38–42 个汉字（`max-width: 40em`） |
| 大标题、小节标题 | 700，字距 -0.015em | 600，字距 0 |
| 小标签（kicker） | 等宽大写，字距 0.12em | 保留英文原样 |
| 图表的标签和数字 | 现在的样式 | 不变；中文说明用正文字体 13–14 px |

- 中文不加负字距，汉字挤在一起不好读。
- 中文粗体用 600，700 在系统中文字体里太黑。
- 标题继续用 `text-wrap: balance`，避免最后一行只剩一两个字。
- 正文用 `text-wrap: pretty`、`line-break: strict`，句末标点不出现在行首。
- 模型名、相机名、路径、`128 × 80` 这类不能断行，加 `white-space: nowrap`。

### 切换

- 中文版地址：`/RoboTeam/zh/`。英文版不变，是默认的版本，不按浏览器语言自动跳转。
- 页头主题按钮旁放 `EN | 中`，记住用户的选择。
- `<html lang="zh-CN">`；两版互相用 `hreflang` 标明，各自的 `canonical` 指向自己。
- 英文页 `site/index.html` 和 `site.js` 是原文。中文对照表是 `site/data/i18n/zh-CN.json`：`text` 是整句对照，原样映射的条目保留英文；`patterns` 处理带数字的句子。
- 中文页 `site/zh/index.html` 由 `python3 -m scripts.site.build_zh` 生成，不手改。改了英文页或对照表后重新生成；测试和发布流程会检查它是否最新。

## 四、README 的图

- 图里的中文用 Noto Sans SC（思源黑体，SIL OFL 1.1），生成时只把用到的字转成轮廓，不把字体文件放进仓库。
- 英文部分仍用 Space Grotesk 和 JetBrains Mono。
- 字号规则和英文版相同：1200 单位宽的图里，最小的字不小于 24 单位，手机上也能读。
- 中文的字号比同一位置的英文大 1–2 单位，汉字在小字号下笔画容易糊。
- 文件名加 `.zh-CN`：`board-light.zh-CN.svg`、`board-dark.zh-CN.svg`。

## 五、宣传片

- 中文字幕用 Noto Sans SC Bold，大小和英文版相同的位置一致。
- 大写的英文标签（RUN START、TASK COMPLETED 等）保留英文。
- 中文句子比英文短，按中文重新排版，不要在英文的位置硬塞中文。
- 文件放在 Hugging Face 的 `film/zh/`，文件名和英文版相同。

## 六、授权

- Noto Sans SC 用 SIL OFL 1.1 授权，附上授权文本，在 `LICENSE-DATA.md` 里登记。
- 苹方、微软雅黑等系统字体只在网页上由访问者自己的电脑显示，不用来生成要分发的图片和视频。
- 中文版文档、README 和网页文字，和英文版用同样的授权（代码 MIT，数据和媒体 CC BY 4.0）。

## 七、检查

- 中英文版的数字一致：自动比对每篇文档里出现的数字。
- 网页的中文文字表不缺条目：自动检查。
- 英文版更新后，对应的中文版要跟上：按每篇开头记录的 commit 检查。
- 中文文档里的链接都能打开：沿用现有的链接检查。
